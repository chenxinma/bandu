# 伴读 bandu S2 拍题识别方案：题目 + 答案定位与三种意图

> 参考：
> - `docs/伴读bandu项目计划.md`（S2 拍题讲解 / 错题本 / 先粗后精策略）
> - EduTutor `CutQuestions`（切题及题目结构化，`edututor:CutQuestions`）
> - 读光教育场景 OCR（公式识别 / 题目识别 / 试卷切题 / 口算判题 / 整页识别 / 精细结构化）
>
> 本文解决 S2 的核心前置问题：**试卷 / 练习册上的"题目 + 答案"位置识别**，以及三种意图（问题解析 / 答案批改 / 错题登记）如何复用同一底座。

---

## 1. 问题定义

拍一张试卷或练习册页面，需要识别出**题目在哪、答案在哪**，才能支撑三种意图：

| 意图 | 定义 | 需要识别的内容 |
|------|------|----------------|
| 问题解析 | 孩子问"这道题怎么做"，引导思考 | 题目区域 + 题干（可忽略答案区） |
| 答案批改 | 判断孩子写的答案对错 | 题目区域 + **学生手写作答** + 标准答案 |
| 错题登记 | 把做错的题归档进错题本 | 题目 + 错答 + 错因标签 |

**核心结论：三种意图共享同一个"定位 + 配对"底座，差异只在下游处理。** 错题登记是答案批改的下游（批改判"错"后触发），不必单独做一次定位。

### 1.1 统一底座输出结构

```json
{
  "qid": "第3题",
  "type": "选择题|填空题|判断题|问答题|作文题",
  "question_box": [x1, y1, x2, y2],
  "question_text": "题干…",
  "options": [{"text": "A. …", "box": [...]}],
  "answer_box": [x1, y1, x2, y2],
  "answer_text": "学生手写作答内容…",
  "answer_state": "answered|blank|illegible",
  "standard_answer": "标准答案…",
  "confidence": 0.87
}
```

## 2. 底座：分层识别架构

```text
第0层 版面检测（定位）
  整页 → 切分出每道题的区域框（bbox）+ 子图
第1层 区域分类
  题干 / 选项 / 插图 / 标准答案 / 学生手写作答 / 空白
第2层 配对（核心）
  题号锚点 + 阅读顺序 + 空间近邻 → 题目 ↔ 答案
第3层 内容理解
  题干 / 选项 / 公式 / 手写内容 / 知识点 / 难度 / 错因
第4层 交互确认
  置信度低 → 孩子点选 / 语音指定 / 重拍
```

- 第 0–2 层（定位 + 配对）是**所有意图的前置**。
- 第 3 层按意图取用不同字段。
- 第 4 层始终保留，对应计划"先粗后精 + 手动圈选兜底"。

## 3. 能力选型：两套阿里云服务

### 3.1 服务清单

| 能力 | EduTutor `CutQuestions` | 读光教育 OCR |
|------|:---:|------|
| 切题 + 题目结构化 | ✅ | ✅ `RecognizeEduPaperCut` / `RecognizeEduPaperStructed` |
| 公式识别 | ✗ | ✅ `RecognizeEduFormula`（印刷体） |
| 题目元素打标（公式/下划线/图片） | ✗ | ✅ `RecognizeEduQuestionOcr` |
| 整页 OCR + 配图坐标 | ✗ | ✅ `RecognizeEduPaperOcr` |
| 判题（口算） | ✗ | ✅ `RecognizeEduOralCalculation` |
| 学生手写作答**定位**（bbox） | ✗（待验证） | ✗（待验证） |
| 学生手写作答**识别** | ✅（可识别手写内容） | ✗（待验证） |
| 手写公式/解题过程识别 | ✗ | ✗ |

### 3.2 覆盖矩阵（对照三种意图）

| 缺口 | 现成能力 | 是否仍需自建 |
|------|----------|:---:|
| 题目侧切题定位 | `CutQuestions` 或 `RecognizeEduPaperCut` | ✗ |
| 数学公式识别 | `RecognizeEduFormula` | ✗ |
| 题目元素打标 | `RecognizeEduQuestionOcr` | ✗ |
| 口算/算术批改 | `RecognizeEduOralCalculation` | ✗ |
| **学生手写作答区定位** | 无明确 API | ✅ 待验证/自建 |
| 手写内容识别 | `CutQuestions` / qwen3.8-flash 均可识别手写 | ✗ |
| **手写公式/解题过程识别** | 无（“印刷体公式”明确限印刷体） | ✅ |
| **简答/解答题语义批改** | 无 | ✅ |

**结论**：题目侧（切题 + 题干/选项/标准答案 + 公式）阿里已封装好；**答案侧**里口算判题、手写内容识别均有现成能力，其余（**手写作答区定位**、非口算批改）需自建。

## 4. 组合架构与数据流

```text
整页试卷图（拍照/扫描）
        │
        ▼
┌─ 题目侧 ─────────────────────────────┐
│ CutQuestions（首选）或 RecognizeEduPaperCut │
│ → 每道题：bbox + 子图 + 题型 + 题干/选项/标准答案 │
└────────────────┬────────────────────┘
                 │ 每道题的 sub_image（切好的子图）
                 ▼
┌─ 精识别层 ───────────────────────────┐
│ RecognizeEduFormula（公式）           │
│ RecognizeEduQuestionOcr（元素打标）    │
└────────────────┬────────────────────┘
                 ▼
┌─ 答案侧（分两条路径）─────────────────┐
│ 口算/算术 → RecognizeEduOralCalculation │
│ 其他 → 手写作答区检测 + 手写 OCR（自建） │
└────────────────┬────────────────────┘
                 ▼
┌─ 内容理解层 ─────────────────────────┐
│ qwen3.8-flash：知识点 / 难度 / 错因    │
│ 教学智能体：提示 / 追问 / 分步 / 引导   │
└────────────────┬────────────────────┘
                 ▼
         三种意图分别取用
```

## 5. 三种意图的下游处理

### 5.1 问题解析

- 取用：`question_text` + `options` + `standard_answer`（供教学策略参考，不直接展示）。
- 走教学智能体"提示 → 追问 → 分步"，**不碰学生答案区**。
- 置信度低 → 要求重拍 / 圈选。

### 5.2 答案批改

- 取用：`question_text` + `standard_answer` + `answer_text`（学生手写作答）。
- **批改 ≠ 直接给标准答案**：产出"对/错 + 错因提示"，不全量报答案（与防直接给答案规则一致）。
- 分路径：
  - 口算/算术 → `RecognizeEduOralCalculation`（现成判题）。
  - 填空/选择（客观题）→ 标准答案比对。
  - 解答/简答（主观题）→ qwen3.8-flash 语义判分（最难，S2 后置）。

### 5.3 错题登记

- 批改判"错"后触发，**不重复定位**。
- 写入错题本：题目（切题结果）+ 错答（手写识别）+ 错因标签（qwen3.8-flash 推断：计算错/概念错/审题错）。
- 错题本结构化存储，按知识点/学科/时间可检索（对应计划 S2 错题本）。

## 6. 手写作答层（自建）

读光教育 OCR 未覆盖的部分，需自建：

```text
手写作答区检测（在单题子图范围内做，难度远低于整页）
  → 手写 OCR（CutQuestions / qwen3.8-flash 均可识别手写内容；读光手写识别 / PaddleOCR 作兜底）
  → 空白/未作答识别
  → 手写公式（数学解答过程）→ 专用公式识别或大模型
```

**待验证**：学生手写作答区 **bbox 定位**仍需自建（CutQuestions 切的是题目区，qwen3.8-flash 无 bbox）；读光 OCR 是否有手写检测/识别接口（`RecognizeHandwriting` 等）降级为可选。

## 7. 鉴权与工程注意点

| 项 | 说明 |
|----|------|
| 鉴权体系 | EduTutor + 读光 OCR 走阿里云 OpenAPI（RAM/AK）；realtime/ASR/TTS 走 Token Plan（Bearer Key）。两套鉴权需统一封装。 |
| 图片输入 | `CutQuestions` 输入为图片 URL（公网可访问），本地图需先上传 OSS / 可公网存储。 |
| 配额 | `CutQuestions` 公测期每天免费 1000 次；读光 OCR 按量计费。S2 DEMO 足够。 |
| 子图时效 | `sub_images` / `merged_image` 为临时 OSS 链接，7 天有效。 |

## 8. S2 分阶段落地建议

| 阶段 | 范围 | 能力 |
|------|------|------|
| S2 第一步 | 单题 + 数学口算/选择题/计算题 | CutQuestions 切题 + 口算判题 + 错题登记，跑通"拍题→批改→错题登记"闭环 |
| S2 第二步 | 数学填空/解答（印刷题） | + 公式识别 + 题目元素打标 + 手写作答区检测 |
| S2 第三步 | 全学科 + 简答语义批改 | + qwen3.8-flash 语义判分 + 手写公式（后置） |

**建议 S2 先收窄到"数学 + 口算/选择/计算题"**：口算判题是现成批改能力，能最快验证产品逻辑；手写作答和简答批改是最大不确定项，后置。
