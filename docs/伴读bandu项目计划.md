# 伴读 bandu 项目计划

> 面向中小学生的语音陪伴型学习助手

---

## 1. 项目概述

### 1.1 产品定位

**伴读** 是一款面向中小学生的语音陪伴型学习助手，核心形态为带摄像头和麦克风的桌面设备。它不是搜题工具，而是一个坐在旁边、会听孩子说话、会引导思考的学习伙伴。DEMO 阶段可用平板或 PC 验证交互体验。

### 1.2 要解决的三个痛点

| 编号 | 痛点 | 典型表现 | 应对策略 |
|------|------|----------|----------|
| P1 | 不把 AI 用在学习上 | 拿设备刷视频、聊与学习无关的天 | 学习模式收束 + 温和转回 + 家长端可见性 |
| P2 | 直接要答案 | 跳过思考过程，只为完成作业 | 分步解锁 + 提示优先 + 求助币机制 |
| P3 | 交互困难 | 拍题识别不准、问题描述不清、等待时间长 | 先粗后精识别 + 语音输入 + 流式反馈 |

### 1.3 项目目标

| 阶段 | 目标 | 核心验收标准 |
|------|------|-------------|
| S1 DEMO | 验证流畅语音对话闭环 | 连续 10 轮对话不崩溃，2 秒内有语音回应，打断 ≤ 1 秒停止 |
| S2 MVP | 加入拍题讲解与教学智能体 | 防跑题拦截率 ≥ 80%，直接给答案率 ≤ 10% |
| S3 Beta | 接入学情画像与家长端 | 3 个年级 × 3 个学科错题归档可用 |
| S4 上线 | 多设备管理与合规上线 | 未成年人数据合规审查通过 |

### 2.3 语音交互双通道方案

**DEMO 阶段以方案 A 为主通道，后续学习讲解切方案 B。**

**方案 A — 实时陪伴对话（主通道）**

```text
麦克风 → AOQ / WebSocket → qwen-audio-3.0-realtime-plus → 文本 + 音频流 → 扬声器
```

适合语音陪伴、闲聊引导、学习状态维持。支持流式音频输入、文本和音频输出，内置 semantic VAD 过滤附和声和背景音。

**方案 B — 教学讲解 Pipeline（学习通道）**

```text
麦克风 → qwen-audio-3.0-asr-flash（流式 ASR）
  → 教学智能体 / 学习策略引擎
  → qwen3.8-flash 或通义千问文本模型
  → qwen-audio-3.0-tts-plus（流式 TTS）
  → 扬声器
```

适合拍题讲解、分步引导、错题归档。ASR、LLM、TTS 独立优化，教学策略不被端到端语音模型锁死。

## 3. 分阶段详细计划

### S1：DEMO 验证（第 1–3 周）

**目标**：跑通「说话 → 识别 → 回复 → 播放 → 打断」完整闭环，验证流畅对话体验。

| 周次 | 任务 | 产出 |
|------|------|------|
| W1 | 百炼实时模型接入，音频采集与播放打通 | 能说话、能听到回复 |
| W1 | 打断逻辑实现（VAD 检测 → 停 TTS → 清缓冲 → 发 interrupt） | 打断响应 ≤ 1s |
| W2 | 教学智能体最小规则（3 条硬编码） | 防跑题 / 防直接给答案 / 追问 |
| W2 | 对话日志 + 每轮延迟埋点 | 可复盘 ASR / TTS / 端到端延迟 |
| W3 | 内部体验测试 + 问题修复 + DEMO 报告 | 正式 DEMO |

**S1 延迟目标**：

| 指标 | 目标值 |
|------|--------|
| 语音首字响应 | ≤ 1.2s |
| ASR 识别延迟 | ≤ 600ms |
| TTS 首包延迟 | ≤ 400ms |
| 打断响应 | ≤ 500ms |
| 端到端对话轮次 | ≤ 2s |

**S1 验收清单**：

- 连续对话 10 轮不崩溃
- 用户说话后 2 秒内有语音回应
- 打断后 1 秒内停止播放
- 明显非学习话题会被引导回来
- 直接问"答案是什么"不给出完整答案
- 对话日志可查看
- 弱网下不卡死，有降级提示

---

### S2：MVP 拍题讲解（第 4–7 周）

**目标**：加入摄像头拍题与分步讲解，验证教学智能体完整能力。

| 周次 | 任务 | 产出 |
|------|------|------|
| W4 | 图像采集 + 页面矫正 + 文字区域检测 | 能拍照并返回题目区域 |
| W4 | 本地粗 OCR + 云端高精度 OCR 并行 | 识别正确率 ≥ 90% |
| W5 | 题目理解（题号 / 题干 / 选项 / 手写 / 知识点 / 难度 / 错因） | 切入方案 B Pipeline |
| W5 | 分步讲解策略引擎（提示 → 追问 → 分步 → 变式题） | 完整教学链路 |
| W6 | 求助币机制 + 答案分步解锁 | 孩子自己决定何时要答案 |
| W6 | 错题本（自动归档 + 错因标签 + 复习提醒） | 数据沉淀能力 |
| W7 | MVP 内部试用（5–10 个真实学生） | 反馈报告 + 迭代清单 |

**S2 拍题识别策略**：

采用 **先粗后精** 方案，而非全自动框选：

1. 本地整页 OCR 快速返回粗结果 → 显示"已识别题目区域"
2. 孩子手动点选或语音指定要问的题目
3. 云端高精度 OCR 二次校正（公式 / 手写 / 复杂版面）
4. 置信度低 → 主动要求重拍（"这道题没拍全，能把镜头再靠近一点吗？"），不硬猜

**S2 防直接给答案机制**：

| 层级 | 策略 | 触发条件 |
|------|------|----------|
| L1 | 提示（"你觉得哪个条件还没用上？"） | 默认所有题目入口 |
| L2 | 追问（"你试了哪一步？卡在哪里？"） | 孩子给出初步尝试 |
| L3 | 分步讲解（第一步 → 第二步 → 完整解法） | 完成前两步互动后解锁 |
| L4 | 求助币解锁完整答案 | 孩子主动消耗 1 币 |
| L5 | 变式题巩固 | 给出答案后自动推送类似题 |

**S2 验收清单**：

- 拍题到首次提示 ≤ 3s
- 识别置信度低时主动要求重拍，不硬猜答案
- 分步讲解至少 3 步交互才给完整解法
- 求助币用完前不解锁完整答案
- 错题本可检索、可按知识点筛选
- 连续使用 30 分钟不出现崩溃或卡顿

### S3：Beta 学情与家长端（第 8–12 周）

**目标**：接入学情画像与家长可见性，形成完整产品闭环。

| 周次 | 任务 | 产出 |
|------|------|------|
| W8–W9 | 知识点图谱构建（数学 / 语文 / 英语 × 3 个年级） | 掌握度模型可用 |
| W8–W9 | 学生画像（年级 / 学科 / 薄弱知识点 / 近期错题） | 个性化推荐能力 |
| W10 | 家长端 App / 小程序（学习时长 / 跑题次数 / 掌握度变化） | 家长可见学习过程 |
| W11 | 内容安全审核 + 敏感话题拦截 | 合规能力就绪 |
| W11 | 未成年人数据隐私：本地优先 + 可关闭 / 导出 / 删除 | 隐私合规 |
| W12 | Beta 公测（50–100 个家庭） | 留存数据 + NPS + Bug 清单 |

**S3 学情数据体系**：

| 模块 | 内容 |
|------|------|
| 学生画像 | 年级、学科、薄弱知识点、最近错题 |
| 掌握度模型 | 每个知识点四级（未掌握 / 初步掌握 / 熟练 / 精通） |
| 错题本 | 自动归档拍照题、错因标签、复习时间 |
| 家长端 | 学习时长、跑题次数、求助次数、掌握度变化趋势 |
| 审计日志 | 所有 AI 输出可回溯，保留版本与时间戳 |

**S3 验收清单**：

- 知识点掌握度按 4 级追踪，数据准确
- 家长端不显示聊天原文，只显示学习行为统计
- 未成年人敏感数据 7 天自动清除
- 内容安全拦截率 ≥ 99.5%
- Beta 用户 7 日留存 ≥ 40%

## 4. 教学智能体设计

### 4.1 核心处理流程

```text
用户输入
  → 意图识别：学习 / 闲聊 / 跑题 / 直接要答案 / 家长设置
  → 学习模式校验：是否允许当前话题
  → 题目理解：知识点 / 难度 / 错因
  → 教学策略选择：
      ├── 跑题 → 温和转回 + 通知家长端
      ├── 要答案 → L1 提示 → L2 追问 → L3 分步 → L4 解锁
      ├── 问题不清 → 主动追问 / 要求重拍
      └── 正常学习 → 分步讲解 + 变式练习
  → 安全审核：敏感内容拦截
  → 输出：语音 + 屏幕分步提示
  → 记录：对话日志 + 错题归档 + 学情更新
```

### 4.2 防跑题策略

- 进入学习模式后，非学习话题不直接拒绝，而是温和转回："这个问题挺有意思的，不过我们现在在做数学作业，做完再聊？"
- 家长端可设置开放范围，而不是完全封死
- 家长端提供学习行为可见性（不是监控），孩子天然在有观众时调整行为

### 4.3 会话状态

每个会话维护以下状态：

```json
{
  "session_id": "sess_001",
  "user_id": "student_001",
  "mode": "learning | chat",
  "last_topic": "数学-几何",
  "answer_unlock_level": 1,
  "help_coins": 3,
  "is_tts_playing": false,
  "interrupted": false,
  "context_window": []
}
```

### 4.4 弱网降级链路

```text
AOQ / WebRTC（首选）
  → WebSocket（降级）
    → 本地文本对话（云端不可用）
      → 本地提示音 + 重拍建议（完全离线）
```

## 5. 接口设计

### 5.1 实时语音对话

```http
POST /api/v1/realtime/chat
Content-Type: application/json

{
  "session_id": "sess_001",
  "user_id": "student_001",
  "mode": "learning",
  "audio_format": "pcm_16k_16bit",
  "enable_interrupt": true
}
```

响应为 WebSocket 流事件：

```json
{ "type": "asr_partial", "text": "这道题为什么" }
{ "type": "asr_final",   "text": "这道题为什么要除以2？" }
{ "type": "tts_audio",   "audio_chunk": "base64_encoded_pcm" }
{ "type": "tts_done",    "session_id": "sess_001" }
{ "type": "agent_action","action": "guide_hint", "hint": "题目给了哪些条件？先找一找。" }
```

### 5.2 打断

```http
POST /api/v1/session/interrupt

{
  "session_id": "sess_001",
  "reason": "user_speaking"
}
```

```http
GET /api/v1/session/logs?session_id=sess_001
```

## 6. 安全与合规要求

| 要求 | 说明 | 阶段 |
|------|------|------|
| 数据最小化 | 不保存未成年人真实姓名、学校、班级 | S1 起 |
| 本地优先 | 敏感数据默认本地存储，云端可关闭 / 导出 / 删除 | S2 起 |
| 日志保留 | 对话日志默认保留 7 天，可配置 | S1 起 |
| 家长可见 | 提供家长查看入口，显示行为统计而非聊天原文 | S3 |
| 内容安全 | 所有 AI 输出经过敏感内容审核 | S1 起 |
| 可回溯 | AI 回复保留版本与时间戳 | S1 起 |
| 话题限制 | 不开放无限制闲聊，学习模式下非学习话题温和转回 | S1 起 |

## 8. 风险与应对

| 风险 | 概率 | 影响 | 应对策略 |
|------|------|------|----------|
| 百炼实时模型首字延迟不达标 | 中 | S1 延期 | W1 即压测，备选方案 B Pipeline（ASR + TTS 独立） |
| 拍题 OCR 对公式 / 手写识别率低 | 高 | S2 体验差 | 先粗后精策略 + 手动圈选兜底 + 要求重拍提示 |
| 教学智能体"太聪明"绕过分步引导 | 中 | P2 痛点未解决 | 规则硬编码优先，LLM 只做策略选择而非直接生成 |
| 未成年人数据合规审查不通过 | 低 | S4 延期 | S3 阶段提前介入合规审查 |
| 硬件方案未定导致端侧无法优化 | 中 | S4 性能风险 | S1–S3 先用平板验证，硬件选型并行推进 |
| 求助币机制被绕过 | 中 | P2 失效 | 家长端可调整币量 + 每日上限 + 行为模式异常告警 |
