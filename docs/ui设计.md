# 语音陪伴助手 UI 设计说明

## 一、 整体布局（9:16 移动端）
采用**沉浸式全屏 + 悬浮层**设计，适配移动端竖屏比例。
*   **背景层**：深色渐变（深蓝/暗紫），突出前景发光效果，减少视觉干扰。
*   **视觉中心（上部 40%）**：呼吸球区域，作为核心视觉焦点，随音频状态动态变化。
*   **对话区（中部 30%）**：半透明毛玻璃气泡，显示用户识别文本与 AI 回复，支持自动滚动。
*   **控制区（底部 30%）**：包含 Mic 音量环、状态提示及打断/停止按钮，符合拇指操作热区。

## 二、 核心视觉元素
**1. 不规则呼吸球（TTS 驱动）**
*   **形态**：基于 Canvas 2D 绘制的多边形顶点平滑曲线，非标准圆形。
*   **动态映射**：
    *   **低频（0-100Hz）**：控制球体整体缩放（呼吸感）。
    *   **高频（100Hz+）**：控制顶点随机扰动（不规则感/毛刺感）。
    *   **能量值**：控制发光强度（`shadowBlur`）与颜色饱和度。
*   **待机状态**：无音频时，执行缓慢的正弦波缩放动画，保持“生命感”。

**2. Mic 音量环（用户输入驱动）**
*   **形态**：环绕 Mic 图标的环形进度条。
*   **动态映射**：
    *   实时计算麦克风音频 RMS（均方根）值。
    *   音量越大，环形填充比例越高，颜色从蓝渐变至红。
    *   无声音时显示微弱底噪波动，避免“死板”。

## 三、 状态与交互逻辑
UI 由**状态机**驱动，确保视觉反馈与后端逻辑一致：

| 状态 | 呼吸球表现 | Mic 音量环 | 交互提示 |
| :--- | :--- | :--- | :--- |
| **Idle (待机)** | 缓慢平滑呼吸 | 隐藏/微弱 | “点击开始对话” |
| **Listening (聆听)** | 随用户音量轻微缩放 | **高亮跳动** | “正在聆听...” |
| **Thinking (思考)** | 快速收缩/旋转 | 隐藏 | “思考中...”动画 |
| **Speaking (播放)** | **不规则剧烈搏动** | 隐藏 | “点击任意处打断” |
| **Interrupted (打断)** | 瞬间收缩回 Idle | 立即恢复显示 | 切回 Listening |

## 四、 技术实现要点
*   **音频分析**：使用 Web Audio API (`AnalyserNode`)，分别建立 TTS 和 Mic 的分析链路。
*   **渲染性能**：使用 `requestAnimationFrame` 驱动，**预分配** `Uint8Array` 缓冲区，避免每帧创建对象导致 GC 卡顿。
*   **平滑处理**：对原始音频数据做线性插值（Lerp），避免 UI 抖动过于剧烈。
*   **兼容性**：处理移动端 `AudioContext` 自动播放限制，确保在用户首次交互后 resume。
